# Zocial 1.13.0

> **Draft — work in progress.** Rolls up the `1.12.x` development line (everything since the **1.12.0** release). New work lands as internal `1.12.1`, `1.12.2`, … dev patches and ships together here as `1.13.0`. Finalise the date and summary when the release is cut.

---

## ✨ Features

- **Quote posts from Mastodon now show inline (from 1.12.1).** Mastodon (4.4 and later) sends quotes in a different format than Akkoma/Pleroma, which Zocial didn't understand, so quoted posts from Mastodon servers were missing entirely. They now appear embedded in the post, just like on Akkoma.
- **Zocial asks before replacing an unsent post (from 1.12.4).** If you closed the compose window with an unfinished post, then clicked Quote, Mention, Edit, Delete & redraft, or shared something into Zocial, the unfinished post was silently thrown away. Zocial now asks first.
- **Several Zocial tabs or windows now work together (from 1.12.5).** A tab you opened earlier used to undo changes made in another one as soon as it saved something: an account you had logged out of came back, a newly added account disappeared, a post you had already sent reappeared as a draft, push settings flipped back. Tabs now take over each other's changes, and a tab showing an account you logged out of elsewhere reloads. The notification sound plays once, not once per open tab.
- **More notification types (from 1.12.5).** Quotes of your posts, edits of posts you quoted, removed connections (after a server or domain block), moderation warnings and the yearly #Wrapstodon now appear as proper notifications instead of "Unhandled notification type", and they no longer show up in the Mentions tab.
- **No duplicate posts after a failed send (from 1.12.4).** If the connection dropped right after tapping Post, the post could already be published while Zocial showed an error; tapping Post again published it a second time. Zocial now marks each post so the server recognises the retry.
- **Clearer error messages (from 1.12.4).** When the server rejects something, the message now includes the server's reason (for example "Validation failed: Text character limit of 500 exceeded") instead of just "Request failed: 422".
- **"Reply to …" header shows reliably (from 1.12.3).** The line above a reply that shows who it answers used to appear only if Zocial happened to have the original post stored, so the same reply sometimes showed it and sometimes didn't. It now appears for replies to yourself, replies to you, and replies to anyone Zocial has seen before, and it loads faster.

## 🐛 Fixes & robustness

- **Word filters now hide images too (from 1.12.1).** A filter set to "hide with a warning" collapsed the post's text, but its images and videos were still shown in full. They are now blurred as well; tap the image to reveal it. This applies even with **Settings → General → Show sensitive media by default** turned on, because a filter is your own explicit choice.
- **Filters also apply to quoted posts (from 1.12.1).** A quoted post matching one of your filters was shown in full inside a post that didn't match. It is now collapsed behind the "Filtered" warning, including filters set to "hide completely", since a quoted post can't be removed on its own.
- **Posts quoting someone you muted or blocked disappear from your timelines (from 1.12.1).** Before, the quote itself silently went missing, and the post was left without its context. Now the whole post is hidden from your home, list and public timelines, the same way that person's own posts are. You still see it in notifications, threads and on profiles. Requires Mastodon 4.5 or later, which tells Zocial about muted and blocked quotes.
- **Quotes no longer vanish without a trace (from 1.12.1).** When a quote can't be shown (for example, it's still pending approval or was deleted), the "RE: link" to the quoted post now stays in the text instead of being removed.
- **Editing or redrafting a Mastodon quote post no longer fails (from 1.12.1).**
- **No more error flood when posts are edited (from 1.12.2).** When a post in your timeline was edited, Zocial could log the same "Cannot read properties of undefined (reading 'id')" error again and again, and the edit wasn't saved locally. Favouriting, boosting or bookmarking that post could also fail with an error message, even though the server had accepted it. The cause was the local post cache remembering "not found" results.
- **No stray error when the emoji set is briefly unreachable while the emoji picker is open (from 1.12.2).** The emoji picker's own background update check is now handled like the rest of the emoji lookups (see 1.12.0).
- **"::" no longer disappears from posts (from 1.12.4).** Text like `std::vector`, IPv6 addresses or CSS selectors lost their double colons in any post, name or bio without custom emoji.
- **GoToSocial profile fields are kept (from 1.12.4).** Saving your profile on a server that allows more than 4 profile fields (GoToSocial allows 6) deleted fields 5 and 6. All existing fields are now kept, and you get as many rows as your server allows.
- **Posts no longer go out without their video (from 1.12.4).** Posting while a file was still uploading published the post without it. The Post button now waits for the upload, and on Mastodon also for the server to finish processing a large video.
- **Editing a post keeps your alt text changes on Mastodon (from 1.12.4).** Changes to image descriptions and focal points made while editing were silently dropped. Existing focal points are also kept now.
- **Delete & redraft keeps a Mastodon quote (from 1.12.4).** Redrafting a post that quoted another one lost the quote.
- **"Hide with a warning" filters catch hashtags at the end of a post (from 1.12.4).** Mastodon usually puts hashtags on their own last line, which Zocial moves into the tag bar; the filter didn't see them there and the post (and its images) stayed uncovered. The same applied to words inside custom emoji.
- **Rejected or pending quotes no longer show up as a preview (from 1.12.4).** When the quoted person declined or revoked a quote, Zocial could still show the quoted post as a link preview card.
- **Favourites and bookmarks refresh properly (from 1.12.4).** These pages loaded the next older page every minute instead of checking for new entries, and kept spinning forever when offline.
- **Fewer broken or missing posts after a longer break (from 1.12.4).** Posts whose stored copy had been cleaned up could leave an empty gap or break a timeline; they are now removed cleanly and come back with the next refresh. Deleted mentions also disappear from the Mentions tab.
- **No more doubled live updates after your phone was asleep (from 1.12.4).** Zocial could end up with two connections to your server after waking up, so every new post arrived twice. A timeline you had left could also keep downloading in the background.
- **Mentions received while the app was asleep reach the Mentions tab (from 1.12.4).**
- **Edits by others show up right away (from 1.12.4)**, instead of only after scrolling the post out of view and back.
- **The profile you're looking at stays the same (from 1.12.4).** Opening the "…" menu of a boosted post on a profile page switched that page's header and Follow button to the boosted author.
- **Favourite, boost, bookmark and pin no longer fail after the server already accepted them (from 1.12.4)** when the browser's local storage was full or busy, and favouriting a post from search results no longer throws an error.
- **Zocial stays fast when left open for days (from 1.12.5).** Timelines kept every post they ever received while open, so a tab left running for days grew to tens of thousands of posts and got slower with each new one. Timelines now keep the newest 500 (older ones load again when you scroll), and only the timelines you visited most recently stay in memory.
- **Push notifications for your other account aren't swallowed (from 1.12.5).** While Zocial was visible, push notifications were suppressed even if the window showed a different account than the one receiving push, so they got lost. Now they are only suppressed when the window shows that account.
- **Replies in a thread are in order (from 1.12.6).** The direct replies to the post you opened could appear out of order after the thread was refreshed; they are now sorted oldest first, like the replies below them.
- **Browser tab title in Spanish, French and Russian (from 1.12.6).** Pages without a logged-in account and the settings pages showed "Zocial" in the tab title instead of the site's address, as they do in English and German.
- **Links in posts always open (from 1.12.4).** Zocial first checks whether a link points to a post or profile it can open itself; on a slow server that check took so long that the browser blocked the new tab. It now waits at most a second.
- **Smaller fixes (from 1.12.4):** translating a long or filtered post showed "undefined" above it; a poll could get one option more than the server allows; picking the same file again after a failed upload did nothing; focus didn't return to the reply button after an inline reply; cancelling the system share sheet showed an error; a failed "Edit" did nothing instead of saying why; a report that failed to send lost the comment you had typed (the report window now reopens with it); profiles with a missing header image or odd date could fail to load; logging out with a revoked token could hide another account from the account list.

## 🐳 Deployment

- **Runtime settings take effect immediately (from 1.12.4).** nginx used to tell browsers to cache every non-hashed file (including `config.js`, the theme files and the service worker's app shell) for 30 days without checking again, so a changed `SINGLE_INSTANCE` could take weeks to reach returning users and a new version could be held back. Only the hashed files under `/client/` are cached permanently now; everything else is revalidated.
- **Safer defaults (from 1.12.4):** the runtime image now follows `nginx:stable-alpine`, so security updates arrive with every build; the container refuses a malformed `SINGLE_INSTANCE` or `TRANSLATE_API` with a clear message instead of starting half-broken; and pushing a Git tag no longer moves the `:latest` image (which Watchtower would have rolled into production).
- **Build on Node 24 LTS (from 1.12.4).** The image is now built with Node 24 instead of Node 20, which reached end-of-life in April 2026, and installs dependencies strictly from the lockfile. The built app is unchanged.

## 🧹 Internal / Code-review results

- **Automated tests and a quality gate (from 1.12.5).** Zocial now has unit tests for the areas that caused problems before, and the linter passes. Both run on every build; if either fails, no new image is built and servers keep running the previous version.
- **More tests (from 1.12.6).** 122 tests now cover translations of the interface, word filters, post ordering, push notifications, login, hashtags, MFM formatting, translation language detection and the local database. They found the two fixes above.
- **Two more reviews (from 1.12.5):** several tabs or windows at once, and tabs left open for days — see the fixes above.

- **General hardening review (from 1.12.4).** A full review of the areas that caused trouble before (timelines and streaming, the local database, rendering, push, login, compose, deployment). Besides the fixes listed above: aborted database operations no longer hang forever, a logged-out account's local data can't be re-created by requests still in flight, the database cleanup can no longer be postponed indefinitely by a busy timeline, a full browser storage no longer breaks logout or posting, and several background tasks log their failures instead of raising uncaught errors. Details in the Architecture handbook (§23).

## 🔐 Security

- **Removed a test login shortcut (from 1.12.4).** An old testing feature inherited from Pinafore let a crafted link (`/?accessToken=…&instanceName=…`) silently replace your session for a server with someone else's account, bypassing the login's CSRF protection. It has been removed. We have no indication that it was ever abused.
- **Extra filtering of post content (from 1.12.4).** Post text is already cleaned by your server and protected by Zocial's Content Security Policy. Zocial now also removes scripts, embedded frames, forms, event handlers and script links itself, for content from servers or bridges that clean less thoroughly. Emoji reaction names and login error messages are escaped too.
- **Protection against clickjacking (from 1.12.4).** Zocial can no longer be embedded in a frame on another website, and responses carry `nosniff` and `no-referrer` headers.
- **Logging out invalidates the login on the server (from 1.12.4).** Until now, logging out only removed the login from your browser; the access token itself stayed valid on your server. Zocial now revokes it. This applies to logins made with this version or later. For older logins, log out and back in once, or revoke Zocial under your server's account settings ("Authorized apps").
- **Removed the old `/migrate` page (from 1.12.4).** It was left over from an earlier domain move and could import login data from a link.
- **Push stops for a logged-out account even when offline (from 1.12.4).** Logging out of the account that receives push notifications now also cancels the browser's push subscription, so notifications stop even if the server couldn't be reached during logout. A push subscription registered with the wrong server key is detected and renewed.
