# Zocial 1.10.0

The headline of this release is a brand-new **dynamic translation system**: the interface language is now a **live, in-app choice** instead of something baked into the build. On top of that, all five languages are brought to **100 % completeness**, the About page gains several new sections, and a broad UI/i18n hardening pass irons out dozens of small inconsistencies.

> This release rolls up **everything since 1.9.0** — including the 1.9.1 and 1.9.2 point releases, which most users never saw as standalone builds. Their changes (**"Remove from followers"** and a **timeline cache-purge on unfollow/block**) are therefore covered in full below alongside the new internationalisation system.

---

## 🌍 Dynamic translation system (headline feature)

Previously the UI language was **fixed at build time** — a German or Russian deployment needed its own image built with `LOCALE=de`, and a running container could never change it. That is gone. Language is now a normal, per-user runtime setting.

- **Pick your language in the app.** A new dropdown under **Settings → General → Interface language**, plus a **language picker on the login screen** (so logged-out users can switch too). Currently English, German, Spanish, French and Russian.
- **Switches instantly — no page reload.** Selecting a language re-renders the whole UI live.
- **One build ships every language.** No more per-language builds; the same image works for everyone.
- **Always-safe defaults.** The app always starts in **English** and falls back to English for any individual string missing in the chosen language — the UI can never render blank or show `undefined`.
- **All five languages are now 100 % complete.** Hundreds of previously-missing strings were translated (German, Spanish, French and Russian had drifted behind English): the whole **word-filter UI**, post scheduling, lists, translation, logs, notification settings, profile editing, followed hashtags, status-header action texts and more. Stale keyboard-shortcut help was refreshed in every language too.
- **Dates, numbers and times follow your language.** Relative times ("3 minutes ago"), join dates, counts and list formatting now use the selected locale, not a fixed build locale.
- **The translation-target dropdown is localised.** The list of translation languages now shows native names in your UI language (e.g. "Spanisch", "Français") via the browser's `Intl.DisplayNames`, instead of the backend's English names.
- **German wording polish.** The playful "Tröt" wording was replaced with "Beitrag/Beiträge" throughout, and the compose button now reads "Post".

**For admins:** the `LOCALE` build variable / `--build-arg LOCALE` **no longer exists** — remove it from any `compose.yaml`, `.env`, CI workflow or build script. Nothing else changes; the language is chosen in-app. All other deploy settings (`SINGLE_INSTANCE`, `TRANSLATE_API`, `PORT`) remain runtime-injectable without a rebuild.

## ✨ Other features

### Remove from followers (from 1.9.1)
- The account **"⋯" menu** now has a **"Remove {account} from followers"** entry for anyone who follows you (Mastodon's `remove_from_followers`) — on every row of the **Followers** list and on the profile of anyone who follows you.
- **Confirms first.** Unlike block or mute (which you can undo yourself), removing a follower can only be undone by the *removed person* re-following you — so this action asks for confirmation before going through, even though Zocial's other menu actions don't.
- **Lights up by itself where supported.** Not every backend implements the endpoint (e.g. GoToSocial currently doesn't); Zocial just tries it and shows a clear "this server doesn't support removing followers" message otherwise — no per-backend allow-list, so it starts working the moment a backend adds support.

### About page
- New **Licence** section (the licence text moved out from under "Credits" into its own heading).
- New **Support & Development** section: links to the user guide, admin guide and the architecture handbook, plus the Zeitfresser Matrix community and the Development & Support channel.
- New **Usage of AI** section, explaining the project's AI-supported-but-rigorously-reviewed development approach, linking the handbook's design philosophy.
- The **version number in the footer** ("Zocial v1.10.0") now links to the releases page.

### Fully translated compose & profile
- The **compose dialog** is now fully localised — the edit/reply/quote headers ("Editing a post", "Replying to a post by …"), the don't-edit/reply/quote buttons, and the poll "Add choice" / "Choice N" labels were previously hardcoded English.
- The **profile tabs** ("Posts", "Posts and replies", "Media") are now translated.

### Consistency
- **Unified empty states.** "Nothing to show" / "No filters" / "You follow no hashtags" / pinned / scheduled / timeline empty states now share one consistent style (centered, deemphasized) instead of each looking different. Each keeps its own descriptive text.
- The **login language picker** is pinned cleanly to the bottom of the card without stretching it or overlapping the footer.

## 🐛 Fixes & hardening

Most of these surfaced while making the UI fully reactive to the live language:

- **"undefined" buttons fixed.** The follow/unfollow and hashtag-add buttons rendered "undefined" in every non-English language. (Those labels are placeholder messages — plain in English but a grammatical variant elsewhere — and were being read from the wrong place.)
- **Empty-list crash fixed.** An empty timeline/list could crash the virtual list (it isn't on the main app store, so its "nothing to show" text needed resolving differently).
- **Labels that were stuck in the boot language now switch live** — settings breadcrumb, page titles, status headers and toolbars, follow buttons, list/empty-state messages, and the compose/settings dropdowns.
- **Pinned posts** now show an empty-state message instead of a blank area when you have none.
- **German status headers read naturally** in the present tense ("X boostet / antwortet an Y") without breaking the "Boosted!" confirmation announcement.
- **Keyboard-shortcut help refreshed** in all languages — adds the `t` (translate) and `a` (bookmark) shortcuts, the `g+i` (instances) and `g+b` (bubble) navigation, and fixes several stale entries/typos.
- **Better timeline error logs.** A recurring "timeline fetch failed: 500" warning now names *which* timeline failed, so a server-side error can be pinned to an endpoint (a 500 is a server error from your instance, not a network/offline issue).

Timeline cache correctness (from 1.9.2):

- **Unfollowing now removes that account's old posts from your home timeline — and your lists.** Previously their already-loaded posts lingered (the timeline cache only ever *adds*, never removes, so a refresh didn't drop them — they only aged out over time). An unfollow now clears them immediately, on screen and from the local cache, matching what the server already does. New posts had already stopped arriving on unfollow; this is only about the old cached ones. Boosts of their posts by people you still follow are kept.
- **Blocking clears them everywhere.** A block removes that account's old cached posts from **all** timelines (home, local, federated, hashtags, lists, profiles) — not just home — immediately and from the local cache.

## 🧹 Internal / Code-review results

- **New runtime i18n engine:** all locale tables bundled, a resolver with a strict *selected → English → key* fallback and an empty-message guard (so a missing/empty/placeholder value can never crash a render), and a reactive `messages` map that templates read directly.
- **Live-reactivity sweep** across ~30 components + the `_static/*` config objects, plus locale-aware `Intl` formatters cached per locale.
- **Audited end-to-end:** every referenced `intl.*` key exists in English; **0 unsafe lookups** remain (the subtle "plain in English but a placeholder elsewhere → undefined" trap was found and eliminated); all four non-English locales verified at 0 missing keys with balanced quoting.
- **Cleanup:** removed the build-time `LOCALE` plumbing entirely (webpack defines, bin scripts, template, emoji wiring), dropped the now-unused `rtl-detect` dependency, and swept 62 leftover debug `console.log`s across 30 files (including two that logged user content).
- **Graceful capability handling (from 1.9.1/1.9.2):** "Remove from followers" detects backend support via runtime 404/501 rather than a maintained allow-list (no Fediverse capability flag exists for it); transient network failures during follow/unfollow/block/remove-follower and a failed account-list refresh now log as warnings, not red errors, matching how the timeline already classifies network noise.
- **Documentation:** the Architecture handbook now covers the runtime i18n model and its pitfalls (§15), the runtime-config / env-injection architecture (§4), the design decision and migration story (§21 [v1.10.0]), and the review outcomes (§23). The README and `.env.example` were trimmed of the obsolete `LOCALE` references.
