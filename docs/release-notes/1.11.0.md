# Zocial 1.11.0

> **Draft — work in progress.** This release rolls up the `1.10.x` development line (everything since the **1.10.0** release). New features and fixes land as internal `1.10.1`, `1.10.2`, … dev patches and ship together here as `1.11.0`. Add to the sections below as more `1.10.x` work lands; finalise the date and the summary when the release is cut.

This is a polish release on top of the big runtime-internationalisation work in 1.10.0. The headline is **automatic language selection on first visit**; the rest is mobile, timeline and robustness fixes.

---

## ✨ Features

### Exclusive lists + a new "Manage lists" page (from 1.10.5)
- **Exclusive lists.** When creating a list you can now tick **"Show posts only in this list"** — the list's members are then hidden from your home timeline and only appear in the list. Ideal for muting high-volume accounts from home while still reading them in a dedicated place. (Server feature; available on Mastodon and GoToSocial.)
- **New "Manage lists" page** under Instance settings (it appears once you have at least one list). From there you can **rename** a list, **delete** it (with a confirmation), toggle **exclusive** on/off per list, and create new lists.
- **Deleting an exclusive list** brings its members' posts back to your home timeline automatically.
- If your server doesn't support exclusive lists, the option is simply hidden (and, in the rare unknown case, a short toast explains it) — no broken toggles.

### Your language is detected on first visit (from 1.10.2)
- On a **fresh visit** (before you've ever picked a language), Zocial now starts in **your browser's language** if it's one we ship, instead of always starting in English. A German or Spanish visitor lands in German/Spanish without touching any setting.
- Matching follows your browser's language preferences in order — an exact match first (e.g. `de`, `ru-RU`), then the base language (`de-DE` → German, `en-GB` → English), and **falls back to English** if none of your languages are available.
- **No flicker.** The language is chosen before the first paint, so there's no flash of English first.
- It's only a starting default: the moment you pick a language in **Settings → General → Interface language** (or the login screen), that choice sticks and overrides detection from then on.

## 🐛 Fixes & robustness

- **Mobile compose no longer jiggles the timeline (from 1.10.1).** Opening **quote / reply** from a post's context menu on a mobile PWA and starting to type used to nudge the timeline behind the dialog on **every keystroke**. The background scroll lock was being applied to the wrong element (`<body>` instead of the actual scroll root); it now correctly locks the page while any dialog is open — on desktop too, where you could previously scroll behind an open dialog.
- **No more rare crash when closing compose quickly (from 1.10.1).** A timing race could leave the autosuggest popup trying to position itself after the compose box was already gone; it now bails out cleanly.
- **Lists and hashtag feeds load more reliably on GoToSocial (from 1.10.1).** GoToSocial assembles list/tag feeds on demand, so the first cold load often returns a server error while it's still building. Zocial already retried timeouts once; it now also retries a single **server error (5xx)** on a blank/stale list or tag view, turning a "won't load on the first try" annoyance into a few-seconds self-heal. A genuinely broken endpoint still falls back gracefully after one retry.
- **List timelines are much more robust on Mastodon too (from 1.10.4).** A list feed is far heavier for the server to assemble than the public timeline, so under load it can drop the connection mid-request — which the streaming "catch-up" fetch (run when the live connection opens or reconnects) used to hammer with up to 15 back-to-back requests, surfacing repeated network errors. That catch-up is now capped (2 requests for list/tag feeds), uses a smaller batch, and fails gracefully instead of throwing — so a flaky connection on a slow list no longer produces a cascade of errors.
- **Smoother scroll-up (from 1.10.1).** Scrolling back **up** a long timeline could visibly re-load preview cards/images (always from cache — no data cost) and make the content jump. A larger render buffer keeps more items mounted, so this happens far less often. (A deeper structural fix is tracked in the handbook backlog.)
- **Timelines render immediately on open (from 1.10.6).** A freshly-opened timeline — most noticeably a brand-new or empty list — could appear blank (not even a loading indicator) until you scrolled or resized the window. The list now measures its layout correctly on open, so content (or the empty/loading state) shows right away.
- **No more page nudge when a dialog opens (from 1.10.3).** On the desktop app (and other setups with a classic, always-visible scrollbar) opening a dialog or the "⋯" menu briefly removed the scrollbar and slid the whole page sideways by a few pixels. The scrollbar's space is now reserved permanently (`scrollbar-gutter: stable`), so the layout stays put — with no effect on platforms that use overlay scrollbars (macOS, mobile).

## 🧹 Internal / Code-review results

- **rAF/rPAF teardown sweep.** Reviewed every animation-frame callback that touches the DOM for the "fires after the component is gone" race and added the missing guards; documented the rule in the handbook (§22). The dialog scroll-lock was reworked to release reliably whether a dialog is closed normally or torn down by navigation (a per-instance, ref-counted lock).
- **Rejected design recorded.** An in-app OS-notification fallback (reviving the old foreground-`Notification()` "System A" path for environments without Web Push) was evaluated and **deliberately not built** — the one case with real value (the Electron desktop app) is already solved by a poller in the Electron wrapper, and a plain PWA can't deliver in the background anyway (the stream freezes). Full rationale in the handbook (§20).
- **Documentation.** The Architecture handbook covers the first-visit language detection (§15, §20 [v1.10.2]), the scroll-lock lifecycle and the rAF/rPAF teardown rule, and the 5xx list/tag retry (§20 [v1.10.1], §22).
